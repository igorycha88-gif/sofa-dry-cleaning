## 1. Цели и задачи

### 1.1 Бизнес-цель
Яркий современный сайт, конвертирующий посетителя в заявку на химчистку дивана через CTA-элементы и интерактивный калькулятор.

### 1.2 Пользовательская ценность
За 30 секунд узнать стоимость чистки своей мебели и оставить заявку в 1 клик.

### 1.3 Метрики успеха
- Конверсия в заявку ≥ 3%
- Lighthouse Performance/SEO/Accessibility ≥ 90 (mobile)
- LCP < 2.5s, CLS < 0.1

---

## 2. Функциональные требования

### 2.1 User Stories

**US-1 Главная страница**
- Given: пользователь открыл `/`
- When: видит hero с градиентным фоном, CTA «Рассчитать стоимость», анимации при скролле
- Then: скролл ведёт по секциям: преимущества (bento) → шаги → калькулятор → до/после → отзывы → FAQ → форма заявки

**US-2 Калькулятор**
- Given: пользователь в секции калькулятора
- When: выбрал тип мебели (7 типов), размер (места/м²), опции (сильное загрязнение, срочно, антибактериальная, удаление запаха)
- Then: мгновенно видит анимированную итоговую цену; кнопка «Оставить заявку» открывает мини-форму (имя + телефон); отправка → POST /api/v1/orders → экран успеха

**US-3 Форма заявки**
- Given: любая форма на сайте (главная, контакты, страницы услуг)
- When: заполнил имя + телефон (+опционально комментарий) и нажал «Отправить»
- Then: валидация на клиенте и сервере; заявка сохраняется в PostgreSQL; уходят 2 SMTP-письма (менеджеру, клиенту если указан email); пользователь видит «Спасибо, заявка принята»

**US-4 Страницы услуг (SEO)**
- Given: пользователь открыл `/uslugi/divan` (или 5 других слагов)
- When: страница открыта
- Then: SSG-страница с описанием, ценами «от», процессом, FAQ (JSON-LD FAQPage) и формой

**US-5 Цены**
- Given: пользователь открыл `/ceny`
- When: видит таблицу прайса по всем категориям
- Then: прайс генерируется из `src/config/pricing.ts`, есть якорь на калькулятор

### 2.2 Требования к анимациям (конверсионная механика)
- Scroll-reveal всех секций (stagger), hover-microinteractions на карточках
- Aurora-фон в hero (CSS), бегущая строка (CSS), анимированный счётчик цены
- Все анимации отключаются при `prefers-reduced-motion`
- Только `transform/opacity` (60 FPS)

## 3. Нефункциональные требования

### 3.1 Производительность
- Страницы — SSG; JS-бандл главной ≤ 180KB gzip
- Анимации не блокируют main thread

### 3.2 Безопасность
- Zod-валидация всех входов API; rate limit 5/60с/IP (Redis) + honeypot
- SMTP-креденшилы только в env; телефоны в логах маскируются

### 3.3 Надёжность
- Ошибка SMTP не валирует заявку (она уже в БД); fail-open rate limit

## 5. UI/UX требования

### 5.1 Стиль
Яркий градиентный (cyan→violet→fuchsia), glassmorphism-карточки, скругления 24px, шрифты Unbounded + Manrope, тёмный текст на светлом фоне, тёмный footer.

### 5.2 Валидация форм
- Имя: 2–100 символов
- Телефон: RU-формат, нормализация к +7XXXXXXXXXX
- Ошибка → красная подсветка + текст под полем

### 5.3 Обработка ошибок
- 429 → «Слишком много заявок, попробуйте через минуту»
- 500 → «Ошибка сервера, позвоните нам: {телефон}»
- Сеть → то же сообщение
