# ADR-001: Общая архитектура сайта химчистки диванов

**Дата:** 2026-10-01
**Статус:** Accepted
**Контекст:** Greenfield-проект. Требуется яркий современный многостраничный сайт с анимациями, интерактивным калькулятором стоимости, формой заявки с SMTP-уведомлениями. Цель — максимальная конверсия в заявку (CTA-ориентированный дизайн).

---

## Решение

Next.js 14 (App Router) монолит: Server Components по умолчанию + островки интерактива (калькулятор, формы) на Client Components. Анимации — Framer Motion + CSS keyframes. Цены — типизированный TS-конфиг (не БД). Заявки — PostgreSQL через Prisma + SMTP-письма (nodemailer). Rate limiting формы — Redis.

---

## Ключевые решения и альтернативы

### ADR-001.1: Анимационная библиотека — Framer Motion

**Вариант А: Framer Motion (Motion for React)** — оценка **9/10**
- ✅ Декларативный API (`whileInView`, `AnimatePresence`, layout-анимации)
- ✅ React-native, поддержка TS из коробки, stagger-эффекты для списков
- ✅ Уважает `prefers-reduced-motion` из коробки (через `useReducedMotion`)
- ❌ +34 KB gzip к клиентскому бандлу

**Вариант Б: GSAP + ScrollTrigger** — 7/10
- ✅ Мощный timeline-контроль, лучший скролл-тelling
- ❌ Императивный, boilerplate в React, «GSAP Premium» за деньги
- ❌ Тяжелее интегрируется с SSR

**Вариант В: Чистый CSS (keyframes + scroll-driven animations)** — 6/10
- ✅ 0 KB JS, нативные `animation-timeline: view()` в 2026
- ❌ Нельзя делать stagger/сценарии, нет физики, совместимость

**Выбор: Framer Motion** для интерактивных сценариев + CSS keyframes для фонов (aurora, marquee) — гибрид даёт 60 FPS и малый JS.

### ADR-001.2: Хранение цен — TS-конфиг, а не БД

**Вариант А: `src/config/pricing.ts` с типами** — **8/10**
- ✅ Типобезопасность, Zod-совместимость, версионирование в git, мгновенный доступ без запросов
- ✅ Сайт остаётся статичным (SSG) — цены подшиваются на этапе сборки
- ❌ Изменение цены = коммит + пересборка (для v1 приемлемо)

**Вариант Б: Таблица `PriceItem` в PostgreSQL** — 6/10
- ✅ Правится без деплоя (нужна админка)
- ❌ Оверкилл для ~20 позиций; ломает SSG; требует ISR/кэш

**Выбор: Вариант А.** При появлении админки — миграция на БД без изменения UI (слой `getPricing()`).

### ADR-001.3: Уведомления о заявках — SMTP (nodemailer)

**Вариант А: nodemailer + SMTP-аккаунт** — **8/10**
- ✅ Прямое требование пользователя; работает с любым провайдером (Яндекс, Mail.ru, корпоративный)
- ✅ 2 письма: менеджеру (мгновенно) + клиенту (подтверждение)
- ❌ Синхронный SMTP — надо защищать таймаутом; спама-риски без rate limit

**Вариант Б: Resend / SendGrid API** — 7/10
- ✅ HTTP API, deliverability выше
- ❌ Внешняя зависимость, тарифы, не соответствует выбору пользователя

**Выбор: Вариант А.** Отправка в фоне (`await` с таймаутом 5с, ошибка SMTP ≠ ошибка заявки — заявка уже сохранена в БД).

### ADR-001.4: Хранение заявок — PostgreSQL + Prisma

- Таблица `Order` + enum `OrderStatus`, `FurnitureType`
- Индекс `@@index([status, createdAt])` для выборки по статусу
- Альтернатива «только email» отвергнута: теряем историю, аналитику конверсии, повторные продажи

### ADR-001.5: Защита формы — Redis rate limit (sliding window)

- `POST /api/v1/orders`: ≤ 5 запросов / 60 сек / IP + honeypot-поле
- Fail-open: если Redis недоступен → пропустить с `logger.error` (сайт не должен терять лиды из-за кэша)

### ADR-001.6: Структура страниц — многостраничник

```
/                    — конверсионная главная (hero → преимущества → калькулятор → до/после → отзывы → FAQ → CTA)
/uslugi              — список услуг
/uslugi/[slug]       — диван / угловой диван / кресло / матрас / ковёр / стул (SEO-лендинги)
/ceny                — таблица цен + калькулятор
/kontakty            — контакты + форма
```

Все контентные страницы — SSG (`generateStaticParams`). API — динамические.

## Влияние на архитектуру

### База данных

```prisma
enum OrderStatus  { NEW CONFIRMED IN_PROGRESS DONE CANCELLED }
enum FurnitureType { SOFA CORNER_SOFA ARMCHAIR MATTRESS CARPET CHAIR OTTOMAN OTHER }

model Order {
  id             String       @id @default(cuid())
  name           String
  phone          String
  email          String?
  address        String?
  furnitureType  FurnitureType
  seats          Int?
  services       String[]     // доп. услуги из калькулятора
  comment        String?
  calculatedPrice Int?        // предварительная цена из калькулятора (копейки не храним)
  source         String?      // страница отправки
  utm            Json?
  status         OrderStatus  @default(NEW)
  createdAt      DateTime     @default(now())
  updatedAt      DateTime     @updatedAt
  @@index([status, createdAt])
}
```

### API

```
POST /api/v1/orders    — создать заявку (Zod-валидация → rate limit → Prisma → SMTP)
GET  /api/health       — healthcheck (DB + Redis ping)
```

## Риски и митигация

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Framer Motion увеличивает бандл / тормозит мобильные | Med | Med | CSS-анимации для фонов; Framer только для сценариев; `prefers-reduced-motion` |
| SMTP-блокировка/таймаут при отправке | Med | High | Таймаут 5с; ошибка письма не валирует заявку (БД уже записана); retry-лог |
| Спам через форму | High | Med | Redis rate limit + honeypot + Zod |
| Утечка SMTP-креденшилов | Low | High | Только через env (`SMTP_HOST`...), никогда не в клиентский бандл |
| Снижение LCP из-за тяжёлых градиентов | Low | Med | Градиенты CSS-only, картинки `next/image` с priority для hero |

## Критерии успеха

- [ ] Все страницы SSG, Lighthouse Performance ≥ 90 (mobile)
- [ ] Анимации 60 FPS (только transform/opacity), respects `prefers-reduced-motion`
- [ ] Заявка сохраняется в БД даже при сбое SMTP
- [ ] Rate limit: >5 заявок/мин с одного IP → 429
- [ ] Каждый API route логирует request/response (Правило 8)
